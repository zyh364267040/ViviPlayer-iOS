# Synthetic regression fixtures

The MP4, M4A and embedded one-pixel artwork are generated by `tools/generate-fixtures.swift` using integer sample formulas and literal test metadata. No downloaded or personal media, external artwork, font or recorded audio is an input. These generated assets, as well as the original app, tests, scripts and documentation, are offered under GPL-3.0-only; see `LICENSE` and `COPYING`.

Run from the repository root on macOS with Xcode command-line tools (verified with Xcode 27.0, build 27A266a):

```sh
mkdir -p .build/module-cache
CLANG_MODULE_CACHE_PATH="$PWD/.build/module-cache" xcrun swift tools/generate-fixtures.swift
shasum -a 256 DrivePlayer/Resources/phase0-test.mp4 DrivePlayerTests/Resources/metadata-fixture.m4a
```

The generator refuses to run outside the project root and intentionally replaces only these two fixed output paths. It writes deterministic ISO BMFF containers without encoder services:

- MP4: 36 synthetic 160×96 YCbCr frames at 12 fps, 3 seconds, H.264 Baseline I_PCM IDR, no audio. The frame at 1 second is used by the live-thumbnail regression test.
- M4A: one second of mono integer triangle-wave samples in ALAC packets, with literal test title, artist, album and lyrics plus a generated 68-byte PNG. This file tests metadata loading, not audible playback.

Two successive generation runs produced the same hashes:

```text
97a30ca7be153e7d29eb2d7c9450a3c0a5c97bd7bb16f6395e9283544db79499  DrivePlayer/Resources/phase0-test.mp4
7fa12c177114d13de42ef047f5c91738551f846312308b1a54c9c5b3b6c1176e  DrivePlayerTests/Resources/metadata-fixture.m4a
```

The M4A is a unit-test resource; the MP4 is an App resource. On an isolated iOS simulator, the three existing AVFoundation metadata/thumbnail regressions passed (3/3), and the complete unit suite passed (558/558). The thumbnail test actually decodes a frame; the M4A tests verify metadata and generated PNG, not sound output. The independent host metadata/container check also passed; host-only video/audio decoding was not established and must not be presented as a media-playback acceptance test.

To rerun the three focused tests, supply your own isolated `SIM_ID` and resolve the pinned dependencies using `Package.resolved`:

```sh
xcodebuild test -project DrivePlayer.xcodeproj -scheme DrivePlayer \
  -destination "platform=iOS Simulator,id=$SIM_ID" \
  -derivedDataPath "$PWD/.build/DerivedData" \
  -only-testing:DrivePlayerTests/MusicMetadataTests/testAVFoundationRawLoaderLoadsRealM4AMetadataForParser \
  -only-testing:DrivePlayerTests/MusicMetadataTests/testDefaultMusicLibraryRefreshAttachesRealEmbeddedM4AMetadataToScannedMusicItem \
  -only-testing:DrivePlayerTests/PlayerScrubLogicTests/testLiveThumbnailServiceGeneratesFrameFromBundledVideo \
  CODE_SIGNING_ALLOWED=NO
```

For menu UI fixtures and tests, see `DrivePlayerUITests/README.md`. Accessibility activation does not establish physical-touch acceptance; Bluetooth vehicle lyrics remain unverified on a real car display.
